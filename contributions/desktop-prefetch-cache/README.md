# 视频缓存设置与有序预缓存（集成材料）

后台默认缓存后续3集，可指定集数或勾选全部剩余集。视频缓存上限默认10GB；空间不足以容纳完整一集时暂停预缓存，保留已有缓存，手动清理或提高上限后继续。当前播放不因后台配额中断。

设置区域放在播放与推荐之间，自动保存、即时生效。目录默认使用应用数据目录下的`video-cache`，支持选择、手输和恢复默认；选盘符时也会使用这个专用子目录。当前播放保留原路径，新播放及后续缓存使用新目录，旧文件不自动搬动。勾选剩余集数后禁用数字输入，默认3、最少1。

界面显示“缓存集数”“手动清理缓存”及“可先手动清理缓存再切换目录”。状态信息在缓存上限行内预留固定空间，错误和清理结果不会推移后续区块。

这是发行仓库的接入材料，包含所需预缓存模块，与现有[#187](https://github.com/waligoraamodio288-rgb/hongguo-desktop-releases/pull/187)有代码重叠。维护者须按[INTEGRATION.md](INTEGRATION.md)接入私有应用源码；合并材料不会改变已发布播放器。未包含私有完整源码、原始bundle、EXE、账号、媒体或用户数据。

完整MP4新增按`stream-cache/剧名 [剧集ID]/季度/剧名_季度_第001集.mp4`存储。剧名明确标注第N季时识别季度，否则为“未分季”；同名剧通过ID区分。`.video-library.json`记录本地身份、文件位置、大小和完整摘要，不存媒体链接或鉴权资料。完整缓存可用本地播放器断网打开；本材料尚未增加应用内离线列表。旧平铺原片仍可读取，不自动迁移。

## 模块

- `desktop_prefetch.py`：当前优先、单转换槽、有序下载、代际取消、实时窗口与容量暂停/恢复。
- `desktop_playable_cache.py`：完整HLS校验、内容及策略指纹、原子提交、独立会话恢复；配置容量时禁用自动淘汰。
- `desktop_video_library.py`：安全命名、剧名/季度目录、持久完整原片索引与校验。
- `desktop_cache_budget.py`：下载和后台转换串行预留容量，完整原片私有暂存后原子发布。
- `desktop_cache_settings.py`：目录、集数和容量配置，原生目录选择、鉴权和安全手动清理。
- `frontend-cache-settings.js`：自动保存与固定单行反馈，需适配宿主React和托管端点入口。

HEVC原生模式只下载原片，不转HLS/H.264；转码模式先完成当前集，再串行准备后续。暂停继续后台工作，缓存命中复用完整产物。原片尺寸未知、单集放不下或预留失败时暂停，不先下载半集凑满空间。下载长度不符、转换失败和超额结果不会发布成有效原片。预留包括下载/解密/封装暂存空间，因而可能在未恰好用满上限时暂停。

清理仅处理明确命名的原片和owner合法且内容已知的HLS；当前播放、转换、正在写入和未知文件保留。前台播放必需的临时输出可能超过设置上限，后台仍停止，不截断播放。

## 验证

Python 3.10+，从仓库根目录运行：

```powershell
pwsh -NoProfile -Command "python -I contributions/desktop-prefetch-cache/tests/run.py"
pwsh -NoProfile -Command "python -I contributions/desktop-prefetch-cache/settings-tests/run.py"
```

预缓存模块77项、设置、容量与视频整理44项测试。第一组无外部依赖；第二组需要FastAPI、Uvicorn和requests，Windows目录选择使用`pwsh.exe`。全部使用自造原片、假HLS和Event，不联网。

本机真实Tauri验证了满额时当前播放继续、全部剩余集预取暂停且不淘汰旧集、手动清理后继续下载完整集。真实剧名识别为第11季，第141集重开后从完整缓存读取，第142集通过真实下载生成命名MP4，并分别完整解码；热切目录后旧HLS仍可读并能释放，手动清理已释放的命名原片会同步移除索引记录。界面验证默认值、专用文件夹、恢复默认、互斥输入、自动保存，以及错误/清理前后区块几何不变。回归中曾遇到上游视频接口返回非JSON，随后真实请求成功；单机结果不承诺其它硬件或网络耗时，fixture不替代宿主验收。
