# 封面图片持久缓存（源码接入材料）

发现、排行榜、探索、搜索、推荐、历史、收藏、合集和单季共用按剧集 ID 保存的图片。读取先检查本地 `poster-cache-v1/<series_id>.cover`，命中直接返回，不再恢复图片地址或访问上游；缺图或坏图才下载并原子保存，切页和重启继续复用。同 ID 并发合并，失败冷却五分钟。

公共入口先批量读取本地，仅缺图进入独立补下载队列。混合批次中的本地图先显示，下载队列占满也不阻塞后来进入页面的缓存图。补下载通过 NDJSON 按完成顺序逐张返回，每张保存后立即显示，不等待整批结束。已有合法图片地址直接开始下载；无关的关系查询和同批缺地址条目不能挡住它。接入时需要取消外层旧封面限流，并确认最终安装资源确实赋值给公共 seriesCover 方法。

本 PR 主要提供后端图片存储逻辑，附公共封面入口的批量适配器和后端/设置最小接入补丁。上游为发行仓库，没有完整应用源码；维护者仍需接入私有宿主并验收、发布，合并材料不会更新客户端。完整应用、EXE、用户图片和数据库均不在本包内。

## 目录与配置

`PosterCache(directory, fetch)` 的 directory 来自现有 CacheSettings.active_root，与视频缓存使用同一个设置根；图片放在其 `poster-cache-v1` 下，各页面复用同一实例。已有目录 junction/symlink 会在启动时解析，复用原生 `.cover` 文件。逐个图片文件的链接不作为缓存命中。

设置目录现在统一控制视频和图片；数据库、收藏/历史和日志仍留在应用数据目录。目录切换先复制已验证的本地图片，再由设置原子保存成功后的同一回调激活新根；在途图片下载共用 ID 锁并跟随新根发布，不重复下载。保存失败不切换当前实例。旧图片保留作恢复，不硬编码盘符或创建页面专属目录。设置标签改为“缓存目录（视频和图片）”，沿用原有视频目录规范化和设置格式，不迁移视频或用户数据库。

## 接入与验证

按 [INTEGRATION.md](INTEGRATION.md) 接入。Python 3.10+、Pillow 和 Node 18+；从仓库根用 pwsh 运行：

```pwsh
pwsh -NoProfile -Command "python -I -B contributions/desktop-poster-cache/tests/run.py"
pwsh -NoProfile -Command "node --test contributions/desktop-poster-cache/tests/test_frontend.cjs"
```

未安装 Pillow 时先在测试环境安装 requirements-test.txt。公开 fixture 使用人工 ID/图片，不连接真实上游。Python 覆盖已有图片零下载、重启复用、并发去重、坏图修复、失败冷却、格式/地址/ID、目录映射、失败原子性、隔离、设置目录切换及在途下载；Node 覆盖批量、去重、并发上限、本地读取不受下载阻塞、逐图显示、分块流解析、部分失败保留和输入验证。

公开基础测试为12项Python和8项Node，另有2项需要已打补丁宿主的并发回归；本次在宿主副本上全部执行通过，未跳过。完整宿主的图片与关系测试共26项通过。真实HTTP流的5项检查确认：详情尚未完成时，已知地址的图片先返回，图片保存后不重复下载。两次实际客户端启动与收藏/历史导航的9项检查通过，均使用正常CSP；99条收藏和51条历史的内容摘要前后一致。额外端口的WebView合成fixture请求未通过，因此采用真实HTTP阻塞测试与正常安装窗口分别验收，不将合成窗口标为通过。公开测试不能替代维护者的私有宿主发布验收，用户图片、数据库与运行profile均不上传。

回滚宿主接线与本包代码即可，保留原图片、地址表及收藏/历史。接入补丁保持旧关系表六列不变，旧版可忽略新增地址表。
