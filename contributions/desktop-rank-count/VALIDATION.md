# 验证范围

2026-10-13实测中，官网同一榜单响应包含下列完整剧集列表，而原桌面排行榜返回0：

| 样本 | 官网及修复后集数 | 原榜单集数 |
| --- | ---: | ---: |
| 药香满院，种田采药赚万金 | 540 | 540 |
| 爆笑姐妹：和闺蜜穿七零带着婆婆一起离 | 162 | 0 |
| 嫌我拍卖行卖假货，当场卖你筑基丹 | 150 | 0 |

本机已安装版本通过10项Python测试、候选11项及安装包12项WebView检查。四种榜单第一页和热播榜第二页均返回20条有效集数；实际卡片显示162集并完成原封面加载。重启日常客户端后，本地服务仍返回162和540集。

请求记录显示5个榜单页各一次官网loader请求，没有首页或详情补数。前端验收期间也未调用原生 `get_rank`、`get_series` 或选集查询来补数字；原封面组件继续使用其既有加载机制。移除首页响应的隔离对照使原来正确的条目也返回0，说明首页补数掩盖了解析遗漏。

`tests/fixtures/rank-samples.json`仅保留四个公开条目的ID、标题和剧集ID列表；去掉请求元数据、描述、图片地址和其他条目。测试不联网，不依赖本机安装目录或额外构建产物。另有前端工厂测试验证参数、请求次数、错误不重试及地址限制。

公开贡献的测试通过只说明这组模块和接入契约通过验证，不能代替维护者私有工程的编译、认证/CORS整合及正式发行验收。官网数据和协议可能变化，结构变化时模块明确报错。
